## 1. Настройка окружения для работы 

Настройка окружения для C++ на Windows с использованием MSYS2, CMake, GDB и VS Code . Такой стек обеспечивает современную, быструю и кроссплатформенную разработку.

Ниже представлена подробная пошаговая инструкция (Qwen).

---

### Шаг 1. Установка MSYS2 и инструментов компиляции

MSYS2 — это менеджер пакетов, который предоставит нам компилятор GCC, отладчик GDB и CMake.

1. Скачайте установщик с официального сайта: [msys2.org](https://www.msys2.org/) и установите его (по умолчанию в папку **C:\msys64**).

*Может придется поискать зеркало и установить не с официального сайта* 

2. После установки запустите терминал **MSYS2 UCRT64** (именно он, так как он обеспечивает лучшую совместимость с современными версиями Windows).


4. Установите компилятор GCC, отладчик GDB, CMake и систему сборки Ninja:
   ```bash
   pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-gdb mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja
   ```

---

### Шаг 2. Добавление путей в переменную среды Windows (PATH)

Чтобы VS Code и терминал Windows «видели» установленные инструменты, нужно добавить их в системный PATH.

1. Нажмите `Win + S`, введите **Изменение системных переменных среды** и откройте.
2. Нажмите кнопку **Переменные среды...**.
3. В разделе «Системные переменные» (или «Переменные среды пользователя») найдите переменную **Path**, выделите её и нажмите **Изменить**.
4. Нажмите **Создать** и добавьте следующий путь:
   ```text
   C:\msys64\ucrt64\bin
   ```
5. Нажмите ОК везде.
6. **Проверка:** Откройте *новое* окно командной строки (`cmd`) или PowerShell и введите:
   ```cmd
   g++ --version
   gdb --version
   cmake --version
   ```
   Если вы видите версии программ — всё настроено верно.

---

### Шаг 3. Установка и настройка VS Code

1. Скачайте и установите [Visual Studio Code](https://code.visualstudio.com/).
2. Откройте VS Code, перейдите во вкладку **Extensions** (Расширения) слева (`Ctrl+Shift+X`) и установите два главных расширения:
   * **C/C++** (от Microsoft) — для подсветки синтаксиса, IntelliSense и отладки.
   * **CMake Tools** (от Microsoft) — для автоматической сборки и управления CMake-проектами.

---

### Шаг 4. Создание тестового проекта

Давайте создадим простейший проект, чтобы проверить связку.

1. Создайте папку для проекта, например `C:\cpp_projects\hello_cmake`.
2. Откройте эту папку в VS Code (`File` -> `Open Folder`).
3. Создайте файл **`CMakeLists.txt`** в корне папки и вставьте туда:
   ```cmake
   cmake_minimum_required(VERSION 3.10)
   project(HelloCMake LANGUAGES CXX)

   # Указываем стандарт C++20
   set(CMAKE_CXX_STANDARD 20)
   set(CMAKE_CXX_STANDARD_REQUIRED ON)

   add_executable(HelloCMake main.cpp)
   ```
4. Создайте файл **`main.cpp`** рядом и вставьте:
   ```cpp
   #include <iostream>
   #include <vector>

   int main() {
       std::vector<int> numbers = {1, 2, 3, 4, 5};
       int sum = 0;
       for (int n : numbers) {
           sum += n;
       }
       std::cout
	```

*С этого места возможны варианты и на первом этапе мы будем запускать код по другому*

### Шаг 5. Настройка VS Code для сборки и отладки



Благодаря расширению **CMake Tools**, вам не нужно вручную писать `tasks.json` или `launch.json`.

1. **Выбор инструмента (Kit):**
   * Нажмите `Ctrl+Shift+P` и введите `CMake: Select a Kit`.
   * В списке найдите и выберите **GCC ... (ucrt64)** или **Unspecified (using compilers [C=gcc, CXX=g++])**. *Важно выбрать именно UCRT64 версию, чтобы избежать проблем с библиотеками Windows.*
2. **Настройка сборки:**
   * Снова `Ctrl+Shift+P` -> `CMake: Select Variant`.
   * Выберите **Debug** (это добавит отладочные символы, необходимые для работы GDB).
3. **Запуск CMake:**
   * В нижней панели VS Code (в статус-баре) появится надпись `[Build]` или `[Configure]`. Нажмите на неё, либо используйте `Ctrl+Shift+P` -> `CMake: Configure`, а затем `CMake: Build` (или `F7`).
   * В терминале VS Code вы увидите, как CMake сгенерировал файлы и Ninja собрал проект.

---

### Шаг 6. Отладка (Debug)

1. Откройте `main.cpp` и поставьте точку останова (breakpoint) на строке `std::cout << "Sum: " << sum << std::endl;` (кликните слева от номера строки).
2. В нижней панели VS Code нажмите на кнопку **Debug** (рядом с кнопкой Build, выглядит как жук 🐞) или нажмите `Shift+F5`.
3. VS Code запустит GDB, программа остановится на точке останова.
4. Вы сможете использовать панель **Debug** слева для просмотра переменных, пошагового выполнения (`F10` / `F11`) и вызовов функций.

---

### 💡 Полезные советы и решение частых проблем

* **Проблема с кодировкой (кракозябры в консоли):**
  Если при выводе в консоль вместо кириллицы вы видите странные символы, добавьте в самый верх вашего `CMakeLists.txt` (после `project(...)`) следующие строки, чтобы заставить GCC использовать UTF-8:
  ```cmake
  if(MINGW)
      add_compile_options(-fexec-charset=UTF-8)
  endif()
  ```
* **Интеграция с терминалом VS Code:**
  Чтобы встроенный терминал VS Code сразу открывался в среде UCRT64, добавьте в `settings.json` (откройте через `Ctrl+Shift+P` -> `Preferences: Open User Settings (JSON)`):
  ```json
  "terminal.integrated.profiles.windows": {
      "MSYS2 UCRT64": {
          "path": "C:\\msys64\\msys2_shell.cmd",
          "args": ["-defterm", "-here", "-no-start", "-ucrt64"]
      }
  },
  "terminal.integrated.defaultProfile.windows": "MSYS2 UCRT64"
  ```
* **Очистка проекта:**
  Если CMake «запутался» в зависимостях, используйте `Ctrl+Shift+P` -> `CMake: Clean Rebuild` или `CMake: Delete Cache and Reconfigure`.
  
## Альтернатива

Отказ от расширений Microsoft (C/C++ и CMake Tools) означает, что мы будем использовать **«чистый» консольный подход**. Это отличный навык, так как он точно повторяет процесс сборки на Linux/macOS и на серверах (CI/CD).

Весь процесс сводится к трем базовым командам CMake: **Конфигурация -> Сборка -> Запуск**.

Ниже приведен порядок действий. Откройте папку проекта в VS Code и откройте встроенный терминал (`Ctrl+~`), желательно **MSYS2 UCRT64** (как мы настраивали в прошлом шаге).

---

### Шаг 1. Конфигурация проекта (Configure)

Современный CMake рекомендует использовать **out-of-source builds** (сборку в отдельной папке), чтобы не засорять исходный код временными файлами.

Выполните в терминале следующую команду:

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
```

**Что здесь происходит:**
* `-B build` — указывает CMake создать папку `build` и поместить туда все сгенерированные файлы сборки.
* `-G Ninja` — указывает использовать генератор Ninja (он намного быстрее стандартного Make и идеально работает с MSYS2). *Если вы не установили Ninja в прошлом шаге, уберите этот флаг, CMake использует стандартный Make.*
* `-DCMAKE_BUILD_TYPE=Debug` — собирает проект в режиме отладки (добавляет символы для GDB и отключает жесткие оптимизации).

*Если в конце вы увидите `-- Build files have been written to: .../build`, конфигурация прошла успешно.*

---

### Шаг 2. Сборка проекта (Build)

Теперь, когда файлы сборки сгенерированы, нужно скомпилировать код. Выполните команду:

```bash
cmake --build build
```

**Что здесь происходит:**
* CMake находит папку `build`, смотрит, какой генератор там использовался (Ninja), и запускает саму сборку.
* В терминале вы увидите процесс компиляции. В конце должно быть написано `[2/2] Linking CXX executable HelloCMake.exe`.

---

### Шаг 3. Запуск исполняемого файла (Run)

После успешной сборки исполняемый файл появится в папке `build`.

Если вы используете терминал **MSYS2 (Bash)**:
```bash
./build/HelloCMake.exe
```

Если вы используете **PowerShell** или **cmd**:
```powershell
.\build\HelloCMake.exe
```

В консоли должен появиться результат работы вашей программы (например, `Sum: 15`).

---

### Шаг 4. Отладка (Debug) без расширений Microsoft

Поскольку мы не используем расширение Microsoft C/C++, у нас есть два пути для отладки.

#### Вариант А: Отладка прямо в терминале (через GDB)
1. Запустите отладчик:
   ```bash
   gdb ./build/HelloCMake.exe
   ```
2. Внутри GDB загрузите исходный код (если он не подгрузился автоматически):
   ```gdb
   file ./build/HelloCMake.exe
   ```
3. Поставьте точку останова на функцию `main`:
   ```gdb
   break main
   ```
4. Запустите программу:
   ```gdb
   run
   ```
5. Программа остановится. Используйте `next` (или `n`) для пошагового выполнения, `print sum` (или `p sum`) для просмотра переменных, `continue` (или `c`) для продолжения. Введите `quit` (или `q`) для выхода.

#### Вариант Б: Отладка в интерфейсе VS Code (Альтернатива Microsoft)
Если вы хотите использовать удобный графический интерфейс отладчика VS Code (с переменными слева, кнопками Play/Step), но без расширений Microsoft, установите расширение **CodeLLDB** (от *Vadim Macagon*). Оно работает на базе LLDB/GDB и является стандартом де-факто для C++ в VS Code, если не используется стек Microsoft.

1. Установите расширение **CodeLLDB**.
2. Создайте в корне проекта папку `.vscode` и файл `launch.json`.
3. Вставьте туда базовую конфигурацию для GDB:
   ```json
   {
       "version": "0.2.0",
       "configurations": [
           {
               "type": "lldb",
               "request": "launch",
               "name": "Debug (CodeLLDB)",
               "program": "${workspaceFolder}/build/HelloCMake.exe",
               "args": [],
               "cwd": "${workspaceFolder}"
           }
       ]
   }
   ```
4. Поставьте точку останова в `main.cpp` и нажмите `F5`.

### 💡 Лайфхак: Автоматизация через `tasks.json`

Чтобы не писать команды вручную каждый раз, можно настроить VS Code так, чтобы сборка запускалась по нажатию `Ctrl+Shift+B`.

1. В VS Code нажмите `Ctrl+Shift+P` -> **Tasks: Configure Default Build Task**.
2. Выберите **Create tasks.json file from template** -> **Others**.
3. Замените содержимое файла на следующее:

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "CMake Configure",
            "type": "shell",
            "command": "cmake",
            "args": ["-B", "build", "-G", "Ninja", "-DCMAKE_BUILD_TYPE=Debug"],
            "group": "build",
            "problemMatcher": []
        },
        {
            "label": "CMake Build",
            "type": "shell",
            "command": "cmake",
            "args": ["--build", "build"],
            "group": {
                "kind": "build",
                "isDefault": true
            },
            "problemMatcher": ["$gcc"]
        },
        {
            "label": "Run Program",
            "type": "shell",
            "command": "./build/HelloCMake.exe",
            "problemMatcher": []
        }
    ]
}
```

**Как пользоваться:**
* `Ctrl+Shift+B` — запустит **CMake Build** (по умолчанию).
* `Ctrl+Shift+P` -> **Tasks: Run Task** — позволит выбрать *Configure*, *Build* или *Run*.

### Резюме (Шпаргалка)
Вся магия CMake без IDE-плагинов сводится к трем командам:
1. `cmake -B build` (создали папку сборки и настроили проект)
2. `cmake --build build` (скомпилировали)
3. `./build/имя_проекта.exe` (запустили)


Отличное уточнение! Папка `build` — это сердце концепции **out-of-source build** (сборки вне исходников), которую настоятельно рекомендует сам CMake. Давайте разберём, как с ней работать, подробно.

---

### 💡 Зачем вообще нужна отдельная папка `build`?

Когда CMake конфигурирует проект, он создаёт десятки временных файлов: `CMakeCache.txt`, `Makefile`, `CMakeFiles/`, объектные `.o` файлы и т.д.

Если собирать «в источниках» (прямо в папке с `main.cpp`), все эти файлы перемешаются с вашим кодом, и вы случайно можете закоммитить их в Git. Отдельная папка `build` решает эту проблему — её можно **удалить одним действием**, и у вас останутся только чистые исходники.

---

### Способ 1. Современный (автоматический, CMake 3.13+)

Флаг `-B build` **сам создаст папку** `build`, если её ещё нет. Вам не нужно делать ничего вручную:

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

Это самый удобный и рекомендуемый сегодня способ.

---

### Способ 2. Классический (ручное создание папки)

Многие туториалы и старые проекты используют «классический» подход — вы сами создаёте папку и заходите в неё. Это полезно знать, так как вы часто встретите его в документации.

#### В терминале MSYS2 (Bash):
```bash
mkdir -p build
cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Debug ..
cmake --build .
```

#### В PowerShell / cmd:
```powershell
mkdir build
cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Debug ..
cmake --build .
```

**Что здесь важно:**
* `mkdir -p build` (или `mkdir build`) — создаёт папку. Флаг `-p` в Bash полезен тем, что не выдаёт ошибку, если папка уже существует.
* `cd build` — заходим внутрь.
* `..` (две точки) в команде `cmake ..` — это путь к `CMakeLists.txt`, который лежит на уровень выше (в корне проекта).
* `.` (точка) в команде `cmake --build .` — означает «собирать в текущей папке».

---

### 🗂️ Как выглядит структура проекта после сборки

После выполнения команд ваша папка проекта будет выглядеть так:

```
hello_cmake/
├── .vscode/              # настройки VS Code
├── build/                # ⚠️ ВСЁ ВРЕМЕННОЕ, не коммитим!
│   ├── CMakeCache.txt
│   ├── CMakeFiles/
│   ├── build.ninja
│   ├── cmake_install.cmake
│   └── HelloCMake.exe    # ← ваш готовый .exe файл
├── .gitignore
├── CMakeLists.txt        # исходник (коммитим)
└── main.cpp              # исходник (коммитим)
```

---

### 🛡️ Обязательно: добавьте `build` в `.gitignore`

Чтобы случайно не отправить артефакты сборки в Git, создайте в корне проекта файл **`.gitignore`** и добавьте туда:

```gitignore
# Папка сборки CMake
build/

# Альтернативные названия папок сборки
out/
cmake-build-*/

# Файлы IDE (на всякий случай)
.vscode/
.idea/
*.swp

# Исполняемые файлы
*.exe
*.o
*.a
*.so
*.dll
```

Теперь `git status` будет игнорировать папку `build`, и ваш репозиторий останется чистым.

---

### 🧹 Как полностью «очистить» проект

Если сборка «сломалась» или вы хотите пересобрать всё с нуля, просто удалите папку `build`:

**В Bash:**
```bash
rm -rf build
```

**В PowerShell:**
```powershell
Remove-Item -Recurse -Force build
```

После этого выполните `cmake -B build ...` заново — и у вас будет абсолютно чистая конфигурация.

---

### 📌 Итог: что нужно помнить

| Действие | Команда |
|---|---|
| Создать папку `build` автоматически | `cmake -B build ...` |
| Создать папку вручную (Bash) | `mkdir -p build && cd build` |
| Создать папку вручную (PowerShell) | `mkdir build; cd build` |
| Указать путь к `CMakeLists.txt` изнутри `build` | `cmake ..` |
| Удалить папку полностью | `rm -rf build` (Bash) / `Remove-Item -Recurse -Force build` (PS) |
| Спрятать от Git | Добавить `build/` в `.gitignore` |

Использование отдельной папки `build` — это профессиональный стандарт в C++ разработке. Привыкайте к нему с самого начала, и в будущем это спасёт вас от многих проблем. 🚀
