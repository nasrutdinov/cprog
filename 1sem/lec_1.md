## Ресурсы и RAII

**Слайд‑заголовок:** Что такое ресурс и RAII  

### Ресурс в C++
Ресурс — это любая внешняя сущность, которой нужно явно управлять:
- динамическая память (`new/delete`, `new[]/delete[]`);
- файловые дескрипторы, сокеты;
- мьютексы, блокировки;
- любые объекты, требующие освобождения/закрытия.

---

## Ресурсы и RAII



### RAII (Resource Acquisition Is Initialization)
- Ресурс захватывается в конструкторе.
- Освобождается в деструкторе.
- Время жизни ресурса привязано к времени жизни объекта.

<div class="highlight"> **Ключевой вывод:** если класс владеет ресурсом, он обязан корректно управлять его временем жизни.
</div>


* Resource Acquisition Is Initialization = Получение ресурса есть инициализация

## Правило трёх

<div class="highlight">
Если классу нужен хотя бы один из этих трёх методов: 

    деструктор, 
    конструктор копирования, 
    оператор присваивания,  
то скорее всего, нужны и остальные.
</div> 


- деструктор (~Class()) — освободить ресурс;
- конструктор копирования (Class(const Class&)) — сделать глубокую копию;
- оператор присваивания копированием (Class& operator=(const Class&)) — корректно перезаписать объект.

---

Правило пяти — это правило трёх плюс семантика перемещения (C++11 и новее):

конструктор перемещения (Class(Class&&));
оператор присваивания перемещением (Class& operator=(Class&&)).
Перемещение нужно, чтобы быстро «передать» ресурс без копирования (например, при возврате из функции или при вставке в вектор).

Правило нуля — современный подход: не писать эти методы вручную, а использовать умные указатели (std::unique_ptr, std::shared_ptr) и другие RAII‑обёртки. Тогда компилятор сам сгенерирует безопасные версии.



## Проблема: поверхностное копирование

**Опасность автоматических методов**  

### Пример «плохого» класса

```cpp
class BadBuffer {
public:
    BadBuffer(size_t n) : size_(n), data_(new int[n]) {}
    ~BadBuffer() {delete[] data_; }
private:
    size_t size_;
    int* data_;
};
```

Что происходит при копировании?

---

**Проблемы**

```cpp 
BadBuffer b2 = b1; 
```

- В этом месте вызывается автоматически сгенерированный конструктор копирования. 
- Копируется только указатель data_ (поверхностная копия).

Теперь два объекта владеют одной памятью. При разрушении первого объекта память освобождается. При разрушении второго — попытка повторного `delete[]` вызывает неопределённое поведение.

Объяснение для студентов 2 курса (уровень «после указателей и динамической памяти»)
В чём проблема
Когда класс владеет ресурсом (например, выделяет память через new), компилятор по умолчанию делает поверхностную копию: просто копирует указатель. В результате два объекта указывают на одну и ту же память. Когда они уничтожаются, деструктор дважды пытается освободить одну и ту же область — это неопределённое поведение (чаще всего — краш программы).

Правило трёх говорит: если классу нужен хотя бы один из этих трёх методов, скорее всего, нужны и остальные:

деструктор (~Class()) — освободить ресурс;
конструктор копирования (Class(const Class&)) — сделать глубокую копию;
оператор присваивания копированием (Class& operator=(const Class&)) — корректно перезаписать объект.
Правило пяти — это правило трёх плюс семантика перемещения (C++11 и новее):

конструктор перемещения (Class(Class&&));
оператор присваивания перемещением (Class& operator=(Class&&)).
Перемещение нужно, чтобы быстро «передать» ресурс без копирования (например, при возврате из функции или при вставке в вектор).

Правило нуля — современный подход: не писать эти методы вручную, а использовать умные указатели (std::unique_ptr, std::shared_ptr) и другие RAII‑обёртки. Тогда компилятор сам сгенерирует безопасные версии.

Пример «плохого» класса (проблема)
cpp
class BadVector {
public:
    BadVector(size_t n) : size_(n), data_(new int[n]) {}
    ~BadVector() { delete[] data_; }

private:
    size_t size_;
    int* data_;
};
Если сделать BadVector b2 = b1;, оба объекта будут владеть одной памятью. При разрушении второго произойдёт двойное освобождение.

Реализация по правилу трёх
cpp
class GoodVector3 {
public:
    GoodVector3(size_t n) : size_(n), data_(new int[n]) {}

    // Конструктор копирования: глубокая копия
    GoodVector3(const GoodVector3& other)
        : size_(other.size_), data_(new int[size_])
    {
        for (size_t i = 0; i < size_; ++i)
            data_[i] = other.data_[i];
    }

    // Оператор присваивания копированием
    GoodVector3& operator=(const GoodVector3& other) {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = new int[size_];
            for (size_t i = 0; i < size_; ++i)
                data_[i] = other.data_[i];
        }
        return *this;
    }

    ~GoodVector3() {
        delete[] data_;
    }

private:
    size_t size_;
    int* data_;
};
Добавляем перемещение (правило пяти)
cpp
class GoodVector5 {
public:
    GoodVector5(size_t n) : size_(n), data_(new int[n]) {}

    GoodVector5(const GoodVector5& other)
        : size_(other.size_), data_(new int[size_])
    {
        for (size_t i = 0; i < size_; ++i)
            data_[i] = other.data_[i];
    }

    GoodVector5& operator=(const GoodVector5& other) {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = new int[size_];
            for (size_t i = 0; i < size_; ++i)
                data_[i] = other.data_[i];
        }
        return *this;
    }

    // Конструктор перемещения
    GoodVector5(GoodVector5&& other) noexcept
        : size_(other.size_), data_(other.data_)
    {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    // Оператор присваивания перемещением
    GoodVector5& operator=(GoodVector5&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = other.data_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    ~GoodVector5() {
        delete[] data_;
    }

private:
    size_t size_;
    int* data_;
};

#include <memory>

class ZeroVector {
public:
    ZeroVector(size_t n)
        : size_(n), data_(std::make_unique<int[]>(n)) {}

    // Никаких деструкторов, конструкторов копирования/перемещения вручную.
    // unique_ptr всё делает безопасно.
