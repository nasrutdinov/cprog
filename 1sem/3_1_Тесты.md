## Память в C++

Для всех заданий общая инструкция для студентов:
> *«Изобразить состояние стека и кучи после выполнения каждой строки кода. Для указателей обозначить, на какую область памяти в куче они ссылаются. Найти все утечки памяти, висячие указатели (dangling pointers) и случаи неопределенного поведения (UB), если они есть.»*

---

### Вариант 1. Классическая перезапись (Базовый)
**Что проверяет:** Понимание того, что перезапись указателя без `delete` приводит к утечке.
```cpp
1. int* p1 = new int(10);
2. int* p2 = new int(20);
3. p1 = p2;
4. delete p1;
5. p2 = nullptr;
```

### Вариант 2. Теневое скрытие переменных (Scope)
**Что проверяет:** Поведение указателей при выходе из области видимости и скрытие имен (shadowing).
```cpp
1. int* ptr = new int(5);
2. {
3.     int* ptr = new int(15);
4.     delete ptr;
5. }
6. delete ptr;
```

### Вариант 3. Несовпадение new[] и delete (UB)
**Что проверяет:** Знание правил парного использования `new[]`/`delete[]` и `new`/`delete`.
```cpp
1. int* arr1 = new int[5];
2. int* arr2 = new int[3];
3. delete arr1; 
4. delete[] arr2;
```

### Вариант 4. Двойное освобождение (Double Free)
**Что проверяет:** Понимание псевдонимов (aliasing) и того, что `delete` не обнуляет указатель автоматически.
```cpp
1. int* a = new int(100);
2. int* b = a;
3. int* c = b;
4. delete a;
5. delete c;
```

### Вариант 5. Массив указателей (Частичная утечка)
**Что проверяет:** Умение работать с массивами указателей и понимание того, что удаление массива указателей не удаляет объекты, на которые они ссылаются.
```cpp
1. int** data = new int*[2];
2. data[0] = new int(1);
3. data[1] = new int(2);
4. delete data;
```

### Вариант 6. Структура с динамическим членом
**Что проверяет:** Управление памятью внутри пользовательских типов данных. Утечка, если не освободить вложенный указатель.
```cpp
 1. struct Node {
 2.     int value;
 3.     int* next_val;
 4. };
 5. Node* n = new Node{5, nullptr};
 6. n->next_val = new int(10);
 7. delete n;
```

### Вариант 7. Ссылки и указатели (Разница в семантике)
**Что проверяет:** Понимание того, что ссылка — это просто псевдоним, и она не владеет памятью.
```cpp
1. int* ptr = new int(42);
2. int& ref = *ptr;
3. ref = 99;
4. delete ptr;
5. int x = ref; // Что здесь произойдет?
```

### Вариант 8. Утечка в цикле (Накопление мусора)
**Что проверяет:** Динамическое выделение памяти в цикле и потеря адресов.
```cpp
1. int* p = nullptr;
2. for (int i = 0; i < 3; ++i) {
3.     p = new int(i * 10);
4. }
5. delete p;
```

### Вариант 9. Двумерный массив (Jagged array)
**Что проверяет:** Сложное выделение и освобождение памяти для многомерных структур.
```cpp
 1. int rows = 2;
 2. int** matrix = new int*[rows];
 3. for(int i = 0; i < rows; ++i) {
 4.     matrix[i] = new int[3];
 5. }
 6. delete[] matrix;
```

### Вариант 10. Комбинированный (Стеки, куча, скоупы, объекты)
**Что проверяет:** Комплексное задание, аналогичное исходному, но с использованием массивов объектов и более сложной логикой скоупов.
```cpp
 1. struct Pair { int x; int y; };
 2. Pair p1{1, 2};
 3. Pair* p2 = new Pair{3, 4};
 4. {
 5.     Pair* p3 = new Pair[2];
 6.     p3[0] = p1;
 7.     p2 = p3;
 8.     delete[] p3;
 9. }
10. delete p2;
```

---

### 💡 Методические рекомендации для преподавателя:

1. **Градуирование сложности:** Варианты 1-4 подходят для первого занятия (базовые утечки и UB). Варианты 5-8 требуют внимательности. Варианты 9-10 — для закрепления и экзамена.
2. **Акцент на UB:** В вариантах 3 и 4 студенты могут просто нарисовать «память освобождена». Важно требовать от них явного указания, что строки `delete arr1` (где `arr1` от `new[]`) или `delete c` (после `delete a`) вызывают **Undefined Behavior**, а не просто «ошибку».
3. **Визуализация:** Требуйте от студентов использовать стрелочки для указателей и явно зачеркивать или писать «ОСВОБОЖДЕНА / UB» в блоках кучи, чтобы они не запутались в собственных рисунках.
4. **Дополнительный вопрос:** К каждому варианту можно добавлять устный вопрос: *«Как исправить этот код, чтобы утечек и UB не было?»* (это переводит студента из режима «критика» в режим «созидатель»).
